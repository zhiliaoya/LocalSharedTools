# LocalShT V3 迭代升级计划书

> **版本**：V3.0-draft ｜ **基线**：V2（[V2 目录](../V2)）｜ **状态**：规划中 ｜ **日期**：2026-11-11
>
> **范围**：本文只描述 V3 的目标、阶段划分与验收标准，不包含实现代码。V3 的新代码统一放在 `V3/`，不修改 V2。

基于 V2 现有代码（单机聊天 / 文件共享，无鉴权）与已定稿的九表权限模型，按「数据层 → 身份 → 权限 → UI 拼接 → 加固」五阶段递进。

**总原则**：复用现有能力、每阶段可独立验收与回滚、后端 `can()` 为唯一安全边界、前端按权限拼装而非隐藏。

## 一、现状与目标

### 1.1 V2 基线核对

为避免计划悬空，先把 V2 的真实状态固定下来（只读核对，未改动 V2）：

| 维度 | V2 现状 | 依据 |
| --- | --- | --- |
| 数据表 | 仅 `messages` 一张表，10 个字段：`id / client_id / username / kind / content / filename / filesize / ext / created_at / ts` | `V2/main.go:271-283` |
| 旧表迁移 | 旧 `texts` 表一次性迁入 `messages`；`ensureColumn` 负责补列 | `V2/main.go:290-298` |
| 路由 | `/ws`、`/history`、`/texts`、`/upload`、`/download`、`/share/info`、`/share/qr`、`/`，全部无鉴权 | `V2/main.go:939-946` |
| 身份 | 浏览器 `localStorage` 自生成 UUID（键 `textshare_cid`），可伪造 | `V2/static/index.html:809-827` |
| WebSocket | `/ws?cid=` 只带 `cid`，无 token | `V2/main.go:499-507`、`V2/static/index.html:1459` |
| 鉴权 | 无；`CheckOrigin` 恒为 `true`，下载仅有共享目录边界校验 | `V2/main.go:496` |
| 运行目录 | `LocalShT/shared`、`LocalShT/data/LocalShT.db` | `V2/main.go:29-32` |
| 构建 | Windows / Linux 双平台；磁盘 / `-tags embedstatic` 双模式；Go 1.27.3 | [V2/README.md](../V2/README.md)、[V2/编译说明.md](../V2/编译说明.md) |

**核心判断**：现有 `messages` 可平滑映射为「记录表」——`kind` → 记录类型、`content` → 文本正文或文件名、`ts` → 时间；无需推倒重来。端口回退、日志双写、静态内嵌、文件分组、二维码生成**全部复用**。

### 1.2 现状与目标

| 维度 | 现状 | 目标 |
| --- | --- | --- |
| 身份 | 浏览器 localStorage 自生成 UUID，可伪造 | 服务端签发 token（= 用户唯一 UUID），状态可控 |
| 角色 | 无 | host / admin / lv1~lv5（角色类型 id 0~6，id 即权限编码） |
| 鉴权 | 无 | token 中间件 + 分享表 + 位掩码 `can()` |
| 数据表 | 仅 `messages` | 九表：角色类型、分享类型、分享等级、token、文件类型、记录、集合、用户、分享 |
| 分发 | 全量广播 | 按接收者可见性过滤后推送 |
| 分享 | 无 | 分享类型 0/1 + 分享等级 + token，接收者 = token |
| 撤销 | 无 | admin 按 `(分享者, token)` 撤销 |
| UI | 全量渲染 | 按 `perm_mask` 组件级拼装，无权节点不生成 |

### 1.3 设计原则

1. **复用优先**：端口回退、日志双写、静态内嵌、文件分组渲染、二维码全部保留，V3 只叠加身份与权限。
2. **单一安全边界**：所有接口与 WS 推送都以服务端 `can()` 判定为准；前端拼装只影响体验，不能替代校验。
3. **可回滚**：每个里程碑独立验收、独立打 tag，保留上一版可执行文件，出问题秒回滚。
4. **独立性**：V3 使用独立目录与独立数据库，不污染 V2；旧表在 M5 前只读保留。
5. **按权限生成，而不是先渲染后隐藏**：无权节点不进入 DOM，避免出现"藏起来的按钮仍能调用接口"的错觉。

### 1.4 目标架构速览

#### 九表清单

| 表 | 定位 | 已知约定 |
| --- | --- | --- |
| `role_types` | 角色类型字典 | id 取 0~6，id 即权限编码；与 host/admin/lv1~lv5 的精确映射 `【待确认】` |
| `share_types` | 分享类型字典 | 取值 0 / 1；两者语义 `【待确认】` |
| `share_levels` | 分享等级字典 | 等级与对应权限掩码 `【待确认】` |
| `tokens` | 身份令牌 | token 值 = 用户唯一 UUID，含 `active` 状态 |
| `file_types` | 文件类型字典 | `0` = 文本；非 0 表示文件 |
| `records` | 记录表 | `kind` → 记录类型，`content` → 文本 / 文件名，`ts` → 时间 |
| `collections` | 记录集合 | 每条记录挂一个默认集合 |
| `users` | 用户 | 关联角色与 token |
| `shares` | 分享 | 分享者、token、分享类型 / 等级 / 目标、`active` |

> 字段级设计在 M1 的 `schema.sql` 中定稿，本文只固化表职责与已知编码，不提前发明列名。

#### 编码与权限约定

| 概念 | 约定 | 备注 |
| --- | --- | --- |
| 角色 | host / admin / lv1~lv5，共 7 个；`role_types.id` 取 0~6 | 具体 id 对应关系 `【待确认】` |
| 权限位 | lv1~lv5 按 1 / 2 / 4 / 8 组合；`perm_mask` 由角色掩码下发 | 五级与四个位如何对应 `【待确认】` |
| 分享类型 | `share_types` 取 0 / 1 | 0 / 1 分别代表全体还是指定 `【待确认】` |
| 分享等级 | `share_levels` 决定分享可携带的权限掩码 | 取值表 `【待确认】` |
| 文件类型 | `file_types.id = 0` 表示文本 | 非 0 表示文件 |
| 身份令牌 | 服务端签发，值等于用户唯一 UUID | 有效期 / 重签 / revoked 语义 `【待确认】` |

#### 请求链路（示意）

```text
HTTP：
  token → authMiddleware → (callerRole, callerUserID, callerToken) → can() → handler → 按权限裁剪响应

WebSocket：
  token → 鉴权 → 注册 client(role/token) → 广播前逐 client 过滤 → 可见才推送
```

## 二、五阶段里程碑

### M1 数据层重建（不改交互，先让表就位）

**目标**：九表建好，旧 `messages` 迁入记录表，服务照常运行。

**任务**

- [ ] 建表（SQLite，沿用 `modernc.org/sqlite`）：
  - 字典：`role_types(id 0~6)`、`share_types(0/1)`、`share_levels`、`file_types(0=文本)`；
  - 实体：`tokens`、`users`、`collections`、`records`、`shares`。
- [ ] 迁移：
  - `messages` → `records`：`text` → `file_type_id=0, content=正文`；`file` → `file_type_id=非0, content=文件名`；
  - 按 `client_id` 聚合 `users`（先 `role=lv2` 占位）+ `tokens`；
  - 每条记录挂默认 `collection`。
- [ ] 双写开关 `-dualwrite`，旧表只读保留，确保可回滚。

**验收**

- 启动正常、历史可见；
- 三表数据量与旧表一致；
- 关双写后旧表不再写入。

**风险**

- 多设备同 `client_id` → 一对一建用户，需人工确认合并。

**预计改动**：`schema.sql`、`migrate.go`、`main.go`（拆分 `initDB`）。

### M2 token 身份与鉴权中间件

**目标**：所有请求带服务端签发 token，中间件解析角色，未授权拒绝。

**任务**

- [ ] token 签发：
  - host 首启生成自身 token（`tokens` + `users(role=0)`）；
  - admin 由 host 生成；普通用户由 admin 生成——**生成即分享**：事务内 `users + tokens + shares` 三写。
- [ ] `authMiddleware`：取 token → 查 `tokens(active)` → 查 `users` 得 `role`，注入 `callerRole / callerUserID / callerToken`。
- [ ] 前端：去掉自生成 UUID，改为换取 token 存本地；`fetch` / `ws` 均携带 token（ws 用 query 或首帧鉴权）。
- [ ] 骨架判定：host 放行、admin 限自有、user 只读可见；无 token → 401。

**验收**

- 三种 token 可区分；
- 无 token 被拒并提示；
- 扫码即得 token（二维码 URL 带 token，复用现有能力）。

**风险**

- 登录嫌麻烦 → 扫码即登录；
- 旧客户端 → 跳转登录页。

**预计改动**：`auth.go`、`main.go`（路由挂中间件）、`static/index.html`（换取并携带 token）。

### M3 权限判定落地（位掩码 + 分享表）

**目标**：权限树 6 条全部生效，判定 O(1)。

**任务**

- [ ] 内存字典（启动载入，`RWMutex` 保护）：
  - `roleMask[0..6]`：host 全位、admin 走分支、lv1~lv5 按 1/2/4/8；
  - `shareLevelMask[id]`。
- [ ] `can(caller, target, need)`：
  - host → true；
  - admin → 校验 `shares(分享者=caller, active)` 覆盖；
  - user → 查 `shares(token=caller, active)`，按「分享类型」解释「分享目标」覆盖 target，再 `(shareMask & roleMask & need) == need`。
- [ ] 接入：`/history /texts /upload /download` 全部前置 `can`；`ws` 广播改为**按接收者过滤**（不可见不推送）。
- [ ] 接口：`POST /share/revoke`（admin，`UPDATE shares WHERE 分享者=caller AND token=目标token`）、`POST /admin/users`（admin，事务三写）。

**验收**

- lv1 只见指定用户文本；
- lv2 能发不能下；
- admin 撤销后目标用户立即失权（HTTP + WS 双生效）。

**风险**

- 广播过滤 O(客户端 × 分享行)，客户端少可接受；多则加 `(token, 状态)` 索引 + 每 client 缓存可见集，分享变更时失效。

**预计改动**：`perm.go`、`main.go`（接口前置 `can` 与广播过滤）。

### M4 UI 按权限拼装（非隐藏）

**目标**：前端按 `perm_mask` **条件生成组件**，无权节点不进 DOM；后端 `can()` 仍是唯一安全边界。

**任务**

- [ ] 后端 `/auth/login`、`/history` 响应下发 `perm_mask`（由 `roleMask[roleId]` 取，与 `can()` 同源）。
- [ ] 前端建组件工厂，全部"条件 append"：
  - `buildComposer(perm)`：有 SEND 才出输入框 / 发送钮，有 UPLOAD 才出 ＋；
  - `buildFileCard(item, perm)`：view 必有，DOWNLOAD 才出 ⬇ 与预览；
  - `buildToolbar(perm)`：仅 lv3/lv5 出多选下载；
  - `buildSettings(perm)`：admin 出"我的分享 + 撤销"，host 出"生成用户"。
- [ ] `renderAll()` 先取 `perm` 再逐节点拼装；历史记录同样按 `perm` 决定是否带下载 / 预览。
- [ ] 删除现有 `body.show-file-check` 等"先渲染后隐藏"的 CSS 开关，改为工具栏不存在。

**验收**

- devtools 搜不到无权节点；
- 各角色 DOM 与权限树一致；
- 越权请求仍 403。

**注意**：perm 由后端下发（前端不自推规则）；拼装不等于免校验，每接口仍走 `can()`。

**预计改动**：`static/index.html`（组件工厂）、`main.go`（`/auth/login`、`/history` 响应）。

### M5 加固与运维（局域网轻量版）

**目标**：稳定、可观测、可恢复。

**任务**

- [ ] 审计：分享变更、生成用户、撤销写日志（可选 `audit_log`）。
- [ ] 备份：启动 `VACUUM INTO` 日快照；共享目录不备份（文件本体）。
- [ ] 下线双写：M1 稳定后移除 `-dualwrite`，旧表归档。
- [ ] 文档：文件名唯一 / 分目录、数组列上限与加锁、撤销只动分享表不吊销 token、token 重签流程。

**验收**

- 断网重连 / 重启一致；
- 越权脚本遍历接口无绕过。

**预计改动**：`audit.go`（可选）、备份与归档逻辑、运维文档。

## 七、结论

1. **V3 是增量升级，不是重写。** 现有 `messages`、广播模型、文件分组、端口回退、日志与静态内嵌都能继续用，改造集中在「身份 + 权限 + 按权限渲染」。
2. **五阶段各自可验收、可回滚。** M1 先让数据就位，M2 再换身份，M3 才收紧权限，M4 做 UI 拼装，M5 加固；任何一步出问题都能退回上一版。
3. **安全边界只有一个。** 后端 `can()` 决定「能不能」，前端 `perm_mask` 只决定「看不看得见」；两者同源，但不能互相替代。
4. **V3 独立目录。** 新版本从 `V2` 复制后演进，V2 保持可运行、可对比，避免版本互相污染。

## 附录 C：术语表

| 术语 | 含义 |
| --- | --- |
| token | 服务端签发的身份凭证，值等于用户唯一 UUID，带 active 状态 |
| role | 角色类型，host / admin / lv1~lv5，对应 `role_types.id` 0~6 |
| perm_mask | 权限位掩码，由角色掩码计算后下发给前端用于组件拼装 |
| 分享等级 | `share_levels`，决定一次分享能携带的权限范围 |
| 记录（records） | 一条文本或文件消息，替代 V2 的 `messages` 行 |
| 集合（collections） | 记录的归组容器，每条记录挂默认集合 |
| 分享（shares） | 分享者把权限授予某个 token 的关系，可撤销 |
| 双写 | M1 过渡期同时写旧 `messages` 与新 `records` 的开关 |

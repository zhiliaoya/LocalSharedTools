# V3 权限矩阵与判定流程

> 实现基线：`perm.go` 中的常量 + `schema.sql` 种子。修改角色掩码只需改 `roleSeeds` 后重建库（或直接改 `role_types` 表并重启）。

## 一、六个权限位

| 位 | 值 | 名称 | 含义 |
| --- | ---: | --- | --- |
| VIEW | 1 | 查看 | 读取 / 接收记录（文本与文件元数据） |
| SEND | 2 | 发文本 | `POST /texts` |
| UPLOAD | 4 | 传文件 | `POST /upload` |
| DOWNLOAD | 8 | 下载 | `GET /download`、图片/视频/PDF 预览、批量下载 |
| SHARE | 16 | 分享管理 | 生成用户、查看自己的分享、撤销 |
| MANAGE | 32 | 全局管理 | 用户列表、重签 token、`/download?file=` |

## 二、角色与掩码

| 角色 | id | perm_mask | VIEW | SEND | UPLOAD | DOWNLOAD | SHARE | MANAGE |
| --- | ---: | ---: | :-: | :-: | :-: | :-: | :-: | :-: |
| host | 0 | 63 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| admin | 1 | 31 | ✓ | ✓ | ✓ | ✓ | ✓ | ✗ |
| lv1 | 2 | 1 | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |
| lv2 | 3 | 3 | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ |
| lv3 | 4 | 11 | ✓ | ✓ | ✗ | ✓ | ✗ | ✗ |
| lv4 | 5 | 7 | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ |
| lv5 | 6 | 15 | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ |

设计理由：

- lv1=只读、lv2=能发不能下，符合计划书验收；
- lv3 / lv5 含 DOWNLOAD，所以「多选下载工具栏 / 文件勾选框」只在这两个等级出现，符合 M4 验收；
- lv4 是上传者（可传不可下）；
- host 全位；admin 含 SHARE 但不含 MANAGE（不能看 host 的用户列表、不能重签）。

## 三、分享类型

| id | 名称 | 解释 |
| ---: | --- | --- |
| 0 | 指定来源 | 接收者只能看到**分享者本人**的记录 |
| 1 | 全体来源 | 接收者可以看到**所有用户**的记录 |

「来源」决定 `can()` 里哪些 owner 的记录可以被这条 share 覆盖；接收者仍然是 `target_token` 对应的用户。

## 四、分享等级

| id | 名称 | 掩码 | 说明 |
| ---: | --- | ---: | --- |
| 1 | 只读 | 1 | 只给 VIEW |
| 2 | 可下载 | 9 | VIEW + DOWNLOAD |
| 3 | 全部数据权限 | 15 | VIEW + SEND + UPLOAD + DOWNLOAD，仍受角色掩码截断 |

接收者的有效掩码：

```text
effective = shareLevelMask & roleMask & need
```

因此 lv2 即使被分享等级 3，也只能拿到 3（VIEW+SEND）；lv3 拿到 11；不会越过角色本身。

## 五、判定流程（`perm.go`）

```text
MaskFor(caller, ownerID):
  caller == nil                         -> 0
  ownerID == caller.UserID              -> caller.PermMask（自有记录按角色）
  caller.RoleID == host                 -> caller.PermMask（全量）
  caller.RoleID == admin:
     存在 active share(sharer=caller, target_token.user_id=ownerID)
                                          -> caller.PermMask
     否则                                 -> 0
  其他角色:
     遍历 active shares(target_token=caller.Token)
       share.type == 0 且 share.sharer_user_id != ownerID -> 跳过
       mask |= shareLevelMask(level) & caller.PermMask
     返回 mask

Can(caller, ownerID, need) := MaskFor(...) & need == need
```

补充规则：

- host 不受分享表限制；
- admin 只覆盖「自己 + 自己创建的活跃分享所对应用户」，不消费别人发给它的分享；
- 撤销分享后该行 `active=0`，下一次 `MaskFor` 立即为 0（HTTP 立即 403 / 历史过滤；WS 推送 `acl_changed` 让前端重载）；
- 重签 token 会把 `shares.target_token` 迁到新 token，旧 token `active=0`。
- 页面 / 设置按角色在服务端组合，admin / host 增量脚本只内联到对应角色页面；客户端代码不是安全边界，接口仍逐个校验。

## 六、接口 × 能力

| 接口 | 需要 |
| --- | --- |
| `GET /` | 任意有效 token；服务端按角色组合页面（未登录跳 `/login`） |
| `GET /login?token=` | 校验 token 后写 Cookie 并跳 `/`；无有效 token 只返回说明页 |
| `GET /history` | VIEW（逐行 `Can(owner, VIEW)` 过滤） |
| `POST /texts` | SEND（自有） |
| `POST /upload` | UPLOAD（自有） |
| `GET /download?msg=` | DOWNLOAD + `Can(owner, DOWNLOAD)` |
| `GET /download?file=` | MANAGE |
| `GET /ws` | 有效 token；历史/广播逐条过滤 |
| `POST /admin/users` | SHARE；host 可建 admin，admin 只能建 lv1~lv5 |
| `GET /admin/users` | MANAGE |
| `POST /admin/users/role` | MANAGE；批量改角色，不能改为 host |
| `POST /admin/users/active` | MANAGE；批量软删除 / 恢复，不能操作 host |
| `POST /admin/users/revoke-token` | MANAGE；批量撤销 token，不能操作 host |
| `GET /admin/shares` | SHARE；host 全部、admin 自有 |
| `POST /share/revoke` | SHARE + host 或本人为 sharer |
| `POST /admin/reissue` | MANAGE；不能重签 host / 已停用用户 |

角色变更后：

- HTTP 请求立即按新 `users.role_type_id` 判定；
- 在线 WS 连接会同步更新缓存的 `Caller`，并收到 `permissions_changed`，前端刷新后按新权限重建 UI；
- 软删除 / 撤销 token 会让目标连接收到 `session_revoked`，token 立即 401；
- 恢复用户只恢复 `users.active=1`，不自动发 token；需 host 重签。


## 七、B1–B16 决策表

| 编号 | 决策 |
| --- | --- |
| B1 | role id：0 host / 1 admin / 2 lv1 / 3 lv2 / 4 lv3 / 5 lv4 / 6 lv5 |
| B2 | 六个权限位见第一节 |
| B3 | lv1=1、lv2=3、lv3=11、lv4=7、lv5=15；admin=31、host=63 |
| B4 | 分享类型 0 指定来源 / 1 全体来源 |
| B5 | 分享等级 1 只读 / 2 可下载 / 3 全部数据权限 |
| B6 | share 行式存储：sharer_user_id + target_token + type + level，无数组列 |
| B7 | admin 只管理自己创建的分享/用户；可访问自有 + 自己创建的分享对应用户 |
| B8 | HTTP `Authorization: Bearer`、WS `?token=`、GET 可 Cookie、扫码 `?token=` |
| B9 | token 无过期；撤销分享不吊销 token；host 可重签 |
| B10 | 迁移按 client_id 一对一；多设备不自动合并，手册给 SQL |
| B11 | 无数组列；单连接串行 + 事务 |
| B12 | 不做跨请求可见集缓存；撤销/重签用 WS 事件失效前端 |
| B13 | `audit_log` 保留最近 5000 行 |
| B14 | 日快照 `VACUUM INTO` + 迁移前快照，默认保留 7 天 |
| B15 | `-dualwrite` 默认 true；false 即下线双写 |
| B16 | 判定顺序：token → user/role → 自有 → host → admin 范围 → share 行 → mask & need |

## 八、示例

| 场景 | 结果 |
| --- | --- |
| host 发文本 | 所有有 VIEW 的用户按来源可见 |
| admin 建 lv1（type 0 / level 3） | lv1 能看到 admin 的文本/文件卡片，但无下载直链 |
| lv2 发文本 | 可以；下载任何文件（含自己的）403 |
| lv3 下载 admin 的文件 | 200（share level 3 & lv3 mask 含 DOWNLOAD） |
| lv4 下载 admin 的文件 | 403（lv4 无 DOWNLOAD）；上传 200 |
| lv1 被撤销分享 | 历史立刻只剩自己的记录；token 仍有效 |
| admin 试图撤销 host 的分享 | 403 |
| host 重签 lv5 | 旧 token 401，旧 WS 收 `session_revoked`，分享迁到新 token |

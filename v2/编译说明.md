# 编译说明

本文件说明如何编译 LocalSharedTools（模块名 `LocalShT`）。

---

## 一、环境要求

| 项目 | 要求 |
|------|------|
| Go | ≥ 1.27.3（见 `go.mod`，当前 `go 1.27.3`） |
| 操作系统 | Windows（主要目标）；Linux 亦支持 |
| CGO | **不需要**（`modernc.org/sqlite` 是纯 Go 实现） |

首次编译前拉取依赖：

```bash
go mod download
```

> **关于 Go 版本**：`go.mod` 当前写的是 `go 1.27.3`。`go` 指令允许 `major.minor` 或 `major.minor.patch`；若希望更低版本也能编译，需要把 `go.mod` 改成 `go 1.26` 之类的下限，并自行验证依赖兼容性。

---

## 二、两种编译模式

项目通过**构建标签（build tag）** 决定是否把 `static/` 目录打包进 exe：

| 模式 | 命令特征 | 运行时依赖 | 适用场景 |
|------|----------|-----------|----------|
| **磁盘模式**（默认） | 不加标签 | 需要 exe 同级或工作目录存在 `static/` 目录 | 开发调试、前端需要频繁改动 |
| **内嵌模式** | `-tags embedstatic` | 无需外部 `static/`，单文件即可运行 | 分发、部署 |

两种模式的差异只在于 `static_embed.go`（`embedstatic`）与 `static_noembed.go`（`!embedstatic`）二选一编译，其余代码完全一致。

---

## 三、编译命令

### 3.1 Windows

**磁盘模式**

```bat
go build -ldflags "-s -w" -o LocalSharedTools.exe .
```

**内嵌模式（推荐用于分发）**

```bat
go build -tags embedstatic -ldflags "-s -w" -o LocalSharedTools.exe .
```

### 3.2 Linux

```bash
CGO_ENABLED=0 go build -tags embedstatic -ldflags "-s -w" -o LocalSharedTools .
```

### 3.3 交叉编译

**在 Linux/macOS 上编 Windows 版：**

```bash
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 \
  go build -tags embedstatic -ldflags "-s -w" -o LocalSharedTools.exe .
```

**在 Windows 上编 Linux 版：**

```bat
set GOOS=linux
set GOARCH=amd64
go build -tags embedstatic -ldflags "-s -w" -o LocalSharedTools-linux .
set GOOS=
set GOARCH=
```

> **注意**：`set GOOS=` / `set GOARCH=` 用完必须清空，否则后续 `go build` 会继续编 Linux 版。

> 说明：`instance_*.go`、`logsetup_*.go` 依赖 `GOOS` 自动选择，无需手动干预。
> `-ldflags "-s -w"` 去除符号表与调试信息以减小体积，不影响 embed 的数据段。

## 四、目录结构与文件职责

```
LocalSharedTools/
├── go.mod
├── go.sum
├── main.go
├── staticfs.go
├── static_embed.go          // 仅 -tags embedstatic 时编译；//go:embed static
├── static_noembed.go        // 默认编译；返回空 FS
├── instance_linux.go        // sameExeOnPort（Linux 空实现）
├── instance_windows.go      // sameExeOnPort（Windows 实现：pidOnPort / exePathOfPID）
├── logsetup.go              // initLogging / detectConsole / pump（平台无关）
├── logsetup_linux.go        // openConsole / clearCloexec（Linux）
├── logsetup_windows.go      // openConsole / clearCloexec（Windows）
├── static/
│   ├── index.html           // 内嵌模式必需；磁盘模式运行时也需存在
│   └── home.jpg / files.jpg / set.jpg   // README 截图
├── LocalShT/shared/         // 运行期自动创建（共享文件）
└── LocalShT/data/           // 运行期自动创建（数据库 + 日志）
```

**文件职责速查（防"复制粘贴到错文件"）：**

| 文件 | 只放什么 | 不要放什么 |
|------|---------|-----------|
| `instance_linux.go` | `sameExeOnPort`（`pidOnPortLinux`，`/proc` 实现） | `openConsole` / `clearCloexec` |
| `instance_windows.go` | `sameExeOnPort`（`pidOnPort` / `exePathOfPID`） | `openConsole` / `clearCloexec` |
| `logsetup_linux.go` | `openConsole` / `clearCloexec` | `sameExeOnPort` |
| `logsetup_windows.go` | `openConsole` / `clearCloexec` | `sameExeOnPort` |

> **踩坑记录**：`instance_linux.go` 曾误留 `openConsole` / `clearCloexec`，与 `logsetup_linux.go` 重复定义，导致 `GOOS=linux go build` 报 `redeclared in this block`。修法是：**`instance_*.go` 只放 `sameExeOnPort`，`logsetup_*.go` 只放 `openConsole` / `clearCloexec`。**

**内嵌模式的三个硬性条件：**

1. `static/` 目录必须位于 `go.mod` 同级的项目根目录（`//go:embed static` 是相对 `static_embed.go` 所在目录解析的）。
2. `static/` 下至少有一个非 `.` / `_` 开头的文件（当前为 `index.html`），否则编译报错：
   ```
   pattern static: no matching files found
   ```
3. Go ≥ 1.16（`//go:embed` 的最低版本要求）。

## 五、验证编译结果

### 5.1 验证前端资源来源

启动日志中（在「===== 启动」之后）会显示前端资源来源：

- 内嵌模式：
  ```
  前端资源来源：内嵌 static/（编译期 embedstatic）
  ```
- 磁盘模式：
  ```
  前端资源来源：磁盘 D:\...\static
  ```

日志文件默认写入 **数据库同目录**（`LocalShT/data/LocalShT.log`）。

### 5.2 验证跨平台编译

**改代码后，建议至少跑一遍两个平台，确认没有"重复定义 / 未定义"：**

```bat
@echo off

:: ========== 编译 Windows 版本 ==========
set CGO_ENABLED=0
set GOOS=windows
set GOARCH=amd64

:: 内嵌网页版本
go build -tags embedstatic -ldflags "-s -w" -o LocalShT-embed.exe .
:: 无嵌网页版本
go build -ldflags "-s -w" -o LocalShT-noembed.exe .

:: ========== 编译 Linux 版本 ==========
set CGO_ENABLED=0
set GOOS=linux
set GOARCH=amd64

:: 内嵌网页版本
go build -tags embedstatic -ldflags "-s -w" -o LocalShT-linux-embed .
:: 无嵌网页版本
go build -ldflags "-s -w" -o LocalShT-linux-noembed .

:: ========== 清理环境变量 ==========
set GOOS=
set GOARCH=
set CGO_ENABLED=
```

> **为什么必须跨平台验证**：`//go:build linux` / `//go:build windows` 的文件在开发机上**只编译当前平台**。另一个平台的"重复定义 / 未定义"在开发机上完全隐形，只有 `GOOS=linux go build` 才暴露。

## 六、运行时说明

```bat
LocalSharedTools.exe
```

可用参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-dir` | `LocalShT/shared` | 共享文件保存目录（自动创建） |
| `-db` | `LocalShT/data/LocalShT.db` | SQLite 数据库路径（父目录自动创建） |
| `-port` | `5050` | 监听端口；被占用时自动向后尝试最多 100 个 |
| `-history` | `200` | 首屏加载的历史消息条数上限 |

示例：

```bat
LocalSharedTools.exe -port 8080 -dir D:\Share -db D:\Share\data.db
```

Windows 下启动后会自动打开浏览器，并在控制台打印本机与局域网访问地址；Linux 不自动开浏览器，需手动打开终端打印的地址。用「设置 → 显示访问二维码」可让手机扫码访问（需同一局域网）。

**单实例检测**：若检测到**同一 exe** 已在 `-port` 上运行，就不再启动第二个实例。Windows 会打开浏览器指向旧实例后退出；Linux 仅记录日志退出。Linux 通过 `/proc/net/tcp*` + `/proc/<pid>/fd` 反查进程，容器内或旧实例属于其他用户时可能探测失败，此时退回端口顺延。

## 七、常见问题

**Q1：编译报 `pattern static: no matching files found`**

内嵌模式下 `static/` 目录缺失或为空。确认目录存在且含 `index.html`，且位于 `go.mod` 同级。

**Q2：运行时报 `static dir not found`**

磁盘模式下找不到 `static/`。程序会依次尝试：
1. exe 所在目录下的 `static/`
2. 当前工作目录下的 `static/`

把 `static/` 放到 exe 旁边，或改用内嵌模式编译。

**Q3：双击 exe 后看不到控制台窗口**

如果你加了 `-H windowsgui`，或程序由任务计划/服务启动，看不到控制台是正常的。日志写入 `LocalShT/data/LocalShT.log`；Windows 下浏览器会自动打开 `http://localhost:5050`。想在终端看实时输出，不要加 `-H windowsgui`，并在终端里启动。

**Q4：端口被占用**

程序会记录 `端口 X 已被占用，尝试下一个...` 并自动切换到后续可用端口，实际端口会在控制台与日志中打印。

**Q5：`GOOS=linux go build` 报 `redeclared in this block` 或 `undefined: sameExeOnPort`**

优先检查文件职责是否串了：
- `instance_linux.go` 只放 `sameExeOnPort` / `pidOnPortLinux`（`/proc` 实现，不要改成空实现）
- `openConsole` / `clearCloexec` 只放 `logsetup_linux.go`

若确实要临时禁用 Linux 单实例检测，也应保留 `sameExeOnPort` 的签名，只让函数体返回 `0, false`，否则 `main.go` 会报 `undefined`。

**Q6：改代码后 Windows 能编、Linux 编不过**

这是 `//go:build` 的常见坑。开发机只编译当前平台，另一个平台的重复/缺失在本地隐形。**每次改跨平台文件后，跑一遍「5.2 验证跨平台编译」的两条命令。**

## 八、一键脚本（可选）

**build.bat**

```bat
@echo off
setlocal
set NAME=LocalSharedTools
set LDFLAGS=-s -w

if /I "%1"=="embed" (
    echo [build] Windows embed mode
    go build -tags embedstatic -ldflags "%LDFLAGS%" -o %NAME%.exe .
) else if /I "%1"=="linux" (
    echo [build] Linux embed mode
    set GOOS=linux
    set GOARCH=amd64
    go build -tags embedstatic -ldflags "%LDFLAGS%" -o %NAME%-linux .
    set GOOS=
    set GOARCH=
) else if /I "%1"=="all" (
    echo [build] Windows embed mode
    go build -tags embedstatic -ldflags "%LDFLAGS%" -o %NAME%.exe .
    if errorlevel 1 exit /b 1
    echo [build] Linux embed mode
    set GOOS=linux
    set GOARCH=amd64
    go build -tags embedstatic -ldflags "%LDFLAGS%" -o %NAME%-linux .
    set GOOS=
    set GOARCH=
) else (
    echo [build] Windows disk mode
    go build -ldflags "%LDFLAGS%" -o %NAME%.exe .
)
if errorlevel 1 exit /b 1
echo [done]
```

用法：

```bat
build.bat          :: Windows 磁盘模式
build.bat embed    :: Windows 内嵌模式
build.bat linux    :: Linux 内嵌模式
build.bat all      :: Windows + Linux 都编（推荐用于发布前验证）
```

> **推荐**：发布前跑 `build.bat all`，一条命令验证两个平台，**不会漏掉"另一个平台的重复/未定义"**。

# V3 运维手册

## 一、首次启动

```bash
cd V3
go run . -port 5050
# 或使用编译好的 exe
LocalShT.exe -port 5050
```

启动后检查控制台 / `LocalShT/data/LocalShT.log`：

- `数据库: ...\V3\LocalShT\data\LocalShT.db`
- `共享目录: ...\V3\LocalShT\shared`
- `Host token 文件: ...\LocalShT\data\host_token.txt`
- 首次启动打印一次 host 登录 URL（带 token），并自动打开浏览器。

### host token 丢失

```bash
LocalShT.exe -host-token 6f1c...新uuid
```

会停用旧 host token 并写入 `host_token.txt`。`token` 建议用 UUID；不要与其他用户 token 重复。

### 登录方式

- **只接受登录链接 / 二维码**：打开 `/login?token=<token>`，服务端校验后写 Cookie 并跳转 `/`；
- 直接访问 `/login` 不再显示 token 输入框：没有有效链接时只显示说明页（401）；
- host / admin 生成用户后，把该**新用户**的登录链接 / 二维码发给对方，手机扫码即登录；
- 页面由服务端按角色组合：普通用户只有聊天 / 基础设置，admin 多出分享面板，host 多出分享 + 用户管理；普通用户不会收到 admin / host 的 HTML 或增量脚本。

> 设置里不再提供「我的登录二维码」：自己的 token / 二维码等同于自己的登录凭证，不要发给他人。

## 二、日常操作

### 生成 admin / 用户

设置 → 「生成用户（生成即分享）」：

- 选择角色（host 可建 admin；admin 只能建 lv1~lv5）；
- 选择来源（指定来源 / 全体来源）与等级（只读 / 可下载 / 全部数据权限）；
- 生成后展示 token、登录链接、二维码。**token 只在此刻完整展示一次**。

也可以直接调：

```bash
curl -X POST http://127.0.0.1:5050/admin/users \
  -H "Authorization: Bearer $HOST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"手机A","role_id":2,"share_type_id":0,"share_level_id":3}'
```

### 撤销分享

设置 → 「我的分享」（host 为「全部分享」）→ 撤销。只把 `shares.active` 置 0，**不吊销 token**；目标用户仍能登录、仍能看自己的记录，只是看不到分享者的记录。

### 重签 token

host 设置 → 「用户管理」→ 重签，或：

```bash
curl -X POST http://127.0.0.1:5050/admin/reissue \
  -H "Authorization: Bearer $HOST_TOKEN" \
  -H "Content-Type: application/json" -d '{"user_id":3}'
```

效果：旧 token `active=0`，旧 WS 收 `session_revoked`，分享行迁到新 token。host 自身用 `-host-token` 重签。

### 批量管理用户（host）

设置 → 「用户管理（host）」：

- 勾选用户 / 全选后，可批量执行：
  - **修改权限**：选择目标角色 → 「修改权限」；不能改为 host；
  - **撤销 token**：让选中用户的当前 token 立即失效，不自动发新 token；
  - **软删除**：`users.active=0` 并撤销 token；记录、分享保留，恢复后需重签；
  - **恢复**：`users.active=1`；不会自动恢复 token，仍需重签。
- 单行也可操作：重签、撤销 token、软删除 / 恢复。
- host 自己没有勾选框，任何批量接口都会拒绝包含 host 的请求。
- 批量上限 200 个用户。
- 角色变更后：在线用户收到 `permissions_changed` 并自动刷新页面；软删除 / 撤销 token 时收到 `session_revoked`，旧 token 立即 401。
- 用户处于软删除状态时不能重签，必须先恢复。

对应接口：

```bash
# 批量改权限
curl -X POST http://127.0.0.1:5050/admin/users/role \
  -H "Authorization: Bearer $HOST_TOKEN" -H "Content-Type: application/json" \
  -d '{"user_ids":[3,4],"role_id":6}'

# 批量撤销 token（不重签）
curl -X POST http://127.0.0.1:5050/admin/users/revoke-token \
  -H "Authorization: Bearer $HOST_TOKEN" -H "Content-Type: application/json" \
  -d '{"user_ids":[3,4]}'

# 批量软删除 / 恢复
curl -X POST http://127.0.0.1:5050/admin/users/active \
  -H "Authorization: Bearer $HOST_TOKEN" -H "Content-Type: application/json" \
  -d '{"user_ids":[3,4],"active":false}'
```

> 普通用户界面与设置不显示角色等级；角色、分享、用户管理入口只在 admin / host 的设置中出现。

### 改昵称

设置里直接改；只影响显示名，不影响身份。历史记录保留当时的 `username` 快照。

## 三、备份与恢复

启动时自动：

- 迁移前：`VACUUM INTO data/backup/pre-migrate-YYYYMMDD-HHMMSS.db`（仅 schema 版本升级时）；
- 每天：`VACUUM INTO data/backup/LocalShT-YYYYMMDD.db`（当天已存在则跳过）；
- 清理超过 `-backup-days`（默认 7）天的日快照；`0` 关闭日快照。

恢复：

```bash
# 停服务
copy LocalShT\data\backup\LocalShT-20261111.db LocalShT\data\LocalShT.db
# 重新启动
```

共享目录 `LocalShT/shared/` 不备份（文件本体）；需要时自行复制。

## 四、从 V2 迁移

1. 停 V2；
2. 备份 V2 的 `LocalShT/data/LocalShT.db`；
3. 复制为 `V3/LocalShT/data/LocalShT.db`（或 `-db` 指向副本）；
4. 启动 V3。

自动动作：

- `messages` 迁入 `records`：文本 `file_type_id=0`，文件按扩展名分成 1/2/3/4/9；
- 按 `client_id` 聚合 `users`、`tokens`、默认 `collections`；
- 每个迁移用户收到 host 的「全体来源 / 全部数据权限」分享，保持旧的全局可见性；
- 迁移用户角色先按 **lv2** 占位（只读 + 发文本）。

按需提升角色（host 登录后执行）：

```sql
UPDATE users SET role_type_id = 6 WHERE name = '旧用户名';  -- lv5：可传可下
```

多设备同 `client_id` 的人工合并（谨慎）：

```sql
-- 查看重复来源
SELECT client_id, count(*) FROM users WHERE client_id <> '' GROUP BY client_id HAVING count(*) > 1;
-- 把 B 的记录并到 A，再停用 B（先备份！）
UPDATE records SET user_id = <A> WHERE user_id = <B>;
UPDATE tokens SET active = 0 WHERE user_id = <B>;
UPDATE users SET active = 0 WHERE id = <B>;
```

## 五、回滚到 V2

1. 停 V3；
2. 方案 A（推荐）：用迁移前快照覆盖 `V2/LocalShT/data/LocalShT.db`；
3. 方案 B：V3 双写开启期间，`messages` 表仍有全部新消息，直接把当前 DB 交给 V2 读取（先确认 `-dualwrite=true` 期间没有关闭过双写）；
4. 启动 V2。

**不要同时运行 V2 和 V3 写同一个数据库。**

关闭双写（进入计划书 M5 状态）：

```bash
LocalShT.exe -dualwrite=false
```

旧 `messages` 表只读保留；`records` 继续正常写入。

## 六、验收清单

### 数据层

- [ ] 首次启动建九表 + `audit_log`，重复启动不报错；
- [ ] 迁移后 `records` 行数 = 旧 `messages` 行数；
- [ ] 文本 `file_type_id=0`，文件非 0；
- [ ] `users` / `tokens` / `collections` 按 `client_id` 聚合；
- [ ] `-dualwrite=true` 时新旧表同步；`false` 时旧表不增。

### 身份

- [ ] host/admin/lv1~lv5 token 均可登录并返回正确 `perm_mask`；
- [ ] 无 token / 无效 token / 已停用 token → 401；
- [ ] 扫码 URL 带 token 可登录；
- [ ] WS 无 token 握手 401。

### 权限

- [ ] lv1 只看得到分享来源的文本/文件卡片；
- [ ] lv2 能发文本、下载 403；
- [ ] lv3 / lv5 能下载、有勾选框/多选工具栏；lv4 能上传、下载 403；
- [ ] admin 撤销后目标用户历史立即减少，WS 收到 `acl_changed`；
- [ ] host 不受分享表限制；
- [ ] 绕过前端直接请求越权接口仍 403。

### UI

- [ ] lv1 devtools 搜不到输入框 / ＋ / 下载链接 / 勾选框 / 管理面板；
- [ ] lv2 有输入框、无 ＋、无下载；
- [ ] lv4 有 ＋、无下载工具栏；
- [ ] lv1~lv5 顶栏不显示角色徽标，设置里只显示用户 ID，不显示权限等级；
- [ ] admin 有「生成用户 / 我的分享」，顶栏与设置显示角色，无「用户管理」；
- [ ] host 有「用户管理」与重签，可勾选 / 全选后批量改权限、撤销 token、软删除、恢复；
- [ ] host 自身没有勾选框；包含 host 的批量请求被 403 拒绝。

### 加固

- [ ] 重启后 token、历史、权限一致；
- [ ] 日快照存在且可恢复；
- [ ] `audit_log` 有 `auth.login / user.create / share.revoke / token.reissue / user.role / user.disable / user.enable / token.revoke`；
- [ ] 旧 token 重签后 401，新 token 200。

## 七、审计与日志

`audit_log` 字段：`at / actor_user_id / actor_role_id / action / detail / ip`。

保留最近 5000 行，启动裁剪。日志同时写 `LocalShT/data/LocalShT.log`。

常见 action：

- `host.bootstrap`
- `auth.login` / `auth.login.fail`
- `user.create`
- `user.role`
- `user.disable` / `user.enable`
- `token.revoke`
- `share.revoke`
- `token.reissue` / `token.reissue.host`
- `profile.update`

## 八、故障排查

| 现象 | 处理 |
| --- | --- |
| 浏览器一直跳登录页 | 检查 Cookie / localStorage `lst_token`、token 是否被重签/停用；重新打开 host/admin 发的登录链接，或让 host 重签后再发链接 |
| 下载 401 | `/auth/me` 会设置 Cookie；刷新页面；确认未清 Cookie |
| 下载 403 | 当前角色无 DOWNLOAD，或分享已撤销，或记录不属于可访问来源 |
| 上传 403 | 角色无 UPLOAD（lv1/lv2/lv3） |
| WS 一直重连 | token 无效或服务未启动；看日志 `/ws` 401 |
| 端口被占 | 自动顺延；二维码使用真实端口；端口上已有同一 exe 时会打开旧实例 |
| 新编译 exe 无法运行（Windows 11） | Smart App Control 拦截未签名程序；代码签名，或在系统设置中关闭智能应用控制 |
| 迁移后旧用户不能下载 | 角色是 lv2 占位；按「从 V2 迁移」提升到 lv5 |
| admin 看不到 host 记录 | 设计如此：admin 只访问自有 + 自己创建的分享对应用户 |
| 忘记 host token | 用 `-host-token` 重签；旧 token 失效 |

## 九、已知限制

- 可信局域网工具：无 TLS、无登录限流、无病毒扫描；
- token 在 WS query / 扫码 URL 中可能进入代理日志；
- 单连接串行写 SQLite，适合局域网小规模；
- 无消息删除 / 搜索 / 分页 / 分享到期；
- 迁移用户角色需手工提升；
- 不支持公网直接暴露。
